## 4. Wire identifiers that are also prompt text

- `update_lens`, `suggest_name`, `apply_result` are simultaneously tool names the model sees (`apply_result` never), persisted part types (`tool-<name>`) on refinement assistant messages, and strings the client reads. `llmcontext.Flatten` echoes only `tool-update_lens` (as `LensEcho`); `ExtractDraftedLensAndSpec` reads `tool-update_lens` and `tool-apply_result` at commit (`refinement.md` § 5); `seedLensTurn` fabricates both when a session opens on an entity with a lens (`refinement.md` § 2).
- `read_thing`, `read_fragment` are persisted as `tool-<name>` parts with their `output` on chat assistant messages and replayed by `Flatten` as an assistant echo plus a user turn of outputs (`context.md` § 7). `read_colour` and the discover-only tools are never persisted as parts; discover transcripts are not stored.
- `propose_brief` is never persisted: its arguments return to the client as the brief response and nothing is created.
- `EditFragmentKind` (`edit`) is both the stored `fragment.type` value and the kind the model reads in the block header; `ContextLegend` quotes it.
- `ThingCitation`'s JSON tags (`ref`, `name`, `kind`, `note`) are the stored shape of `fragment_annotation.things`, read back by `mapping` and by the colour thing-rematch (`colours.md` § 3).
- The kind vocabulary the annotate and consolidate prompts dictate (`person, organisation, place, project, topic, other`) is `mapdoc.Kinds`; `mapdoc.NormalizeKind` folds `organization` / `company` / `org` to `organisation` and anything else unknown to `other`.
- The cadence words in `ProposeCadenceParamDescription` and the `propose_reflection` schema enum map to grid periods `24h`, `168h`, `720h`, `2160h` in `discover/reflections.go`; the model never sees the durations.
