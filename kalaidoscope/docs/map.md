## 1. Objects

- **The document** (`kalaidoscope_map`, singleton, server-written — `DisableWriteOperations`): `body` is one JSON document `{things[], relationships[], narrative}`; `version` increments per consolidation; `consolidated_at` is stamped per consolidation; `created`/`updated` autodates. There are no other fields (no counters). The worker's `loadDocument` takes the first row (`sourcedata.FindMapRecord`: filter `1=1`, limit 1, no sort; it never checks for a second) and, when there is none, creates one with `version 0` and no `body` — so the row is born on the first annotation or consolidation, whichever comes first. The read-only accessor `sourcedata.LoadMapDocument` never creates the row: absent, it returns an empty document at version 0. A body that is empty, `{}`, `null`, unparseable, or lacks a `things` key parses (`mapdoc.Parse`) as an **empty** document; the parse's failure flag is discarded by every caller (`mapping.loadDocument`, `sourcedata.LoadMapDocument`), so a corrupt body is indistinguishable from a fresh map. `pbutil.RawJSONField` also yields `""` (hence an empty document) when the stored field cannot be unmarshalled as raw JSON.
- **A thing** (`mapdoc.Thing`): `{id, name, aliases[], kind, blurb, fragments, first_seen?, last_seen?, exemplar_ids[]}` (`first_seen`/`last_seen` are `omitempty`). `kind` ∈ `person`, `organisation`, `place`, `project`, `topic`, `other` (`mapdoc.Kinds`); `NormalizeKind` lower-cases and trims, maps `organization`/`company`/`org` to `organisation`, and anything else not in the list to `other`. Ids are minted server-side (`mapdoc.MintID`): `t_` + 8 lower-case unpadded base32 chars from 5 `crypto/rand` bytes (a random-read failure panics). `fragments`, `first_seen`, `last_seen`, `exemplar_ids` (≤ 5, `maxExemplars`) are recomputed at every consolidation from citations, never taken from the model.
- **A relationship** (`mapdoc.Relationship`): `{from, to, kind}` by thing id.
- **An annotation row** (`fragment_annotation`, one per fragment, unique index `idx_fragment_annotation_fragment` on `fragment_id`, relation to `fragment` with cascade delete, server-written): `title`, `summary`, `things` (exactly the model's citations after parsing: `{ref}` or `{name, kind, note}` — a citation with both `ref` and `name` keeps only `ref`; one with neither is dropped), `decisions`/`questions`/`conclusions` (`[{text, refs[]}]`, always written, possibly `[]`; the parser drops items with empty `text` and removes blank refs), `consolidated_at` (empty until a consolidation reads the row; secondary index `idx_fragment_annotation_consolidated_at`), `generated_from_map_version` (the `kalaidoscope_map.version` whose document was in the prompt), `generated_by_model`, `created`. The row has no `updated` autodate.
- **A run** (`map_run`, server-written, never pruned): one per consolidation attempt that reached the model-call stage — `status` (`running`/`done`/`error`), `error`, `generated_by_model`, `pending_in`, `admits`, `merges`, `version_before`, `version_after`, `created`, `updated`.

## 2. Annotation (the worker drain)

**The worker.** `mapping.Worker` is built once by `workers.New` (`internal/workers/manager.go`) via `NewWorker(app)`; nothing runs until `Worker.Run(ctx)`, which starts `annotateLoop` and `consolidateLoop` in an `errgroup` and returns `ctx.Err()` once both have stopped. The manager starts it at serve time (`runtime.start`, after the `OnServe` chain's `se.Next()`) and cancels it at terminate, waiting up to 10 s (`boot-and-workers.md` § 2).

**Pending set** (`sourcedata.PendingAnnotationFragments`) = every `fragment` with `deleted_at = ''` whose id has no `fragment_annotation` row, computed by loading every annotation row (`AnnotatedFragmentIDs`) and every live fragment and diffing in memory, then stably sorted: fragments with `ingested_via != "import"` first, then by `occurred_at` ascending within each group. `sourcedata.PendingAnnotationCount` is the size of this set, by the same full load (§ 6).

**Two wake methods, one signal.** `signal` is a `workerutil.Signal`: a buffered channel of capacity 1 whose `Notify` is a non-blocking send (a wake already waiting is not duplicated). `SignalAnnotate()` is `Notify`. `Signal()` sets the `wantSettle` flag and then calls `SignalAnnotate()`. `annotateLoop` takes, per wake: the after-drain callbacks registered so far (`followUps.Detach()`, below), then `wantSettle.Swap(false)` — so a full (settling) drain is one whose flag was set before it started. Because the channel holds one wake, several signals coalesce into one drain; a `Signal()` that lands while a drain is running leaves the flag set and a wake queued, so it is honoured by the drain *after* it, never lost. Callers outside the worker's own methods — `SignalAnnotate`: the `OnRecordAfterCreateSuccess("fragment")` hook in `server.RegisterTriggers` when `ingested_via != "import"` (`ingestion.md` § 7), and `ingest.processIngestRecord` at the end of an async import whose `organize_after` is false (unconditionally, even when the import wrote no fragments; `ingestion.md` § 3); `Signal`: `POST /api/map` (§ 5) and `ingest.startPipeline`, the post-import chain (`ingestion.md` § 4). Inside the worker, `KickIfPending()` calls `SignalAnnotate` when the pending set is non-empty and is called once at boot by `Manager.BootKicks` (a pending-count error is swallowed and no signal is sent).

**After-drain callbacks.** `AfterDrain(fn func(err error))` appends a one-shot callback to a `workerutil.Callbacks` queue. Each drain runs only the callbacks that were queued *before* it began (`Detach` at the top of the pass), after the drain — and its settle cycle, if any — completes, with the drain's error; a callback added mid-drain runs after the next drain. Nothing in this package calls `Signal` on behalf of a queued callback — the caller does. The sole registrant is `ingest.startPipeline`, which queues a callback and then itself calls `Signal()`; the callback, on a nil error, calls `discover.Signal` for `colours`, `projections`, `reflections` in that order, and on a non-nil error returns without signalling discover (`ingestion.md` § 4, `discover.md` § 2).

**The drain.** Per wake, `annotateLoop` sets `annotating` true, runs `drain(ctx, full)`, clears the flag, stores the result as `LastDrainError` (the error's message, or `""` on nil), logs it unless it is `context.Canceled`, and invokes the detached callbacks with it. `drain` resolves `llm.RoleAnnotate` once (`llm.ResolveRole`; a resolution failure returns immediately — no fragments, no settle cycle even for a full drain, and the error becomes `LastDrainError`). Then it loops: return `ctx.Err()` if the context is done; recompute the pending set; drop fragments already marked failed in this drain; stop when nothing remains. Within an iteration up to 100 (`annotateWorkers`) fragments are annotated concurrently through an `errgroup` limit; the dispatch loop stops handing out fragments once any goroutine has recorded `usage.ErrExhausted` (or the context is done), waits for in-flight ones, and on exhaustion breaks out of the outer loop too. Each `annotateOne`:

1. Loads the document (`loadDocument`, fresh per fragment — a later fragment in the same drain sees things admitted by a consolidation that landed meanwhile) and records its `version`.
2. Builds one user message: `prompts.AnnotatePrompt(doc, prompts.FragmentBlock(type, source, id, content))`. The map block lists only things with `fragments >= 2` (`annotateInlineFloor`), relationships whose both ends are among the listed things, and the narrative; a map with no listed things and an empty narrative gets the one-line `annotateEmptyMap` notice instead. Things with fewer than 2 citing fragments are invisible to the annotator.
3. One call via `usage.GenerateOnceMsgsThrottled` at `RoleAnnotate` with the resolved model and no tools (registry options: temperature 0; scheduler priority `Background` by `queue.DefaultPriorityForRole`, `llm-queue-quota.md` § 2.1). The wrapper is `usage.RetryThrottled`: `queue.ErrPreempted` is re-entered at once without limit; a `llm.ProviderError` of kind `quota` or `transient` is retried with exponential back-off (initial 2 s, capped at 1 min, giving up after 3 min elapsed); any other error — including `usage.ErrExhausted` from the period quota, which is not a `ProviderError`, and a stream cut short by context cancellation — returns at once (`llm-queue-quota.md` § 4).
4. `prompts.ParseAnnotateReply`: takes the text between the first `{` and the last `}`, requires it to be a JSON object with a `summary` key, and requires a non-empty trimmed `summary`. On failure the conversation is extended with the assistant reply and `prompts.MapJSONRetryNudge` and the call is made **once** more; still unparseable → error `unparseable annotate reply`.
5. Creates the `fragment_annotation` row: `fragment_id`, `title`, `summary`, the four JSON fields, `generated_from_map_version` = the version loaded in step 1, `generated_by_model` = the resolved model. `consolidated_at` is left empty.

A failure is logged, marks the fragment failed for the rest of this drain (it is retried on the next signal), and — if first — becomes the drain's error; the goroutine itself returns nil so one failure never stops the others. After the loop, a full drain whose context is still live runs one **cycle** (§ 3.2) — even when the loop ended on quota exhaustion or annotated nothing; an annotate-only drain ends here and leaves the rows for the consolidate timer. `Annotating()` reports true from before `drain` starts until it returns, so it also covers a full drain's settle cycle and its settle hooks. A drain that ends on a done context returns `ctx.Err()` itself, so `LastDrainError` then reads `context canceled`.

## 3. Aggregation

### 3.1 When consolidation is due

`consolidateLoop` ticks every 10 s (`consolidateTick`, `time.NewTicker`, first tick 10 s after `Run`; the ticker stops and the loop returns `ctx.Err()` on cancellation). Each tick, `consolidateDue` queries `fragment_annotation` rows with `consolidated_at = ''`, newest `created` first: a query error is logged and the tick skipped; no rows → not due; more than 50 rows (`consolidatePendingFloor`) → due; otherwise due when the newest such row's `created` is more than 1 minute old (`consolidateStaleAge`). When due the tick runs a **cycle** (§ 3.2). When not due the tick does nothing. Boot does not itself trigger a consolidation; the first tick does if rows qualify. The due rule is the only thing the timer evaluates — it does not look at the pending set, at `Annotating()`, or at the document.

### 3.2 A cycle

`cycle(ctx)` = `integrate(ctx)` followed by every registered settle hook, in registration order, outside the mutex; `settle` (the name a full drain calls) is `cycle`. `integrate` takes `consolidateMu`, sets `Consolidating()` true, runs `consolidate` (§ 3.3, error logged and dropped), clears the flag and releases the mutex — so `Consolidating()` is true for the whole of `integrate`, including a `consolidate` that finds nothing to do. Two cycles can be requested at once (a full drain's settle and a timer tick); the mutex serialises their `integrate` phases, and the second typically finds no unconsolidated rows and returns without a run row — its settle hooks still run.

**Settle hooks (emitting side).** `OnSettle(fn func(core.App))` appends to a slice on the worker with no locking (the doc comment says to register before `Run`); every hook runs after every cycle regardless of whether the consolidation did anything, succeeded, or failed. Hooks run synchronously on the calling goroutine — inside a full drain (so before its after-drain callbacks and before `Annotating()` clears) or inside the timer tick. Subscribers, registered in `workers.New` immediately after the workers are constructed, in this order:

1. `colour.Worker.OnMapSettled` — reads the document's version (`sourcedata.LoadMapDocument`) and the `fragment_annotation` row count, and recomputes thing-backed colour membership only when either differs from the pair it saw at the previous settle (`colours.md` § 3).
2. `reconcile.Worker.OnMapSettled` — calls `EnqueueWave()`, which is a no-op unless the auto-wave policy is on (`reconcile.md` § 4).

`WaitSettled()` locks and immediately unlocks `consolidateMu`: it blocks while an `integrate` is in progress and returns once it is not. It does not wait for the settle hooks, for an in-progress annotation drain, or for a consolidation that is *due* but not yet started. Its one caller is `discover.run`, after resolving its model and before loading the map (`discover.md` § 2).

### 3.3 Consolidation

`consolidate(ctx, app)` returns nil at once when no `fragment_annotation` row has `consolidated_at = ''` (this is the silent skip; no run row). Otherwise, with `pending` = those rows (oldest `created` first):

1. Loads **all** annotation rows via `sourcedata.LoadAnnotationRows` (§ 4) — consolidated and unconsolidated alike — indexes their citations by fragment id, loads the current document, and resolves `llm.RoleMap` (a failure in any of these returns before any run row is written).
2. Creates a `map_run` with `status = running`, `generated_by_model`, `pending_in` = len(`pending`), `version_before` = the loaded version. A failure to save the run aborts the consolidation.
3. One user message: `prompts.ConsolidatePrompt(doc, rows)` — the current map as JSON of `{things[{id,name,aliases,kind,blurb}], relationships, narrative}` (counts and dates omitted), or the first-run notice when the map has no things and an empty narrative; then **every** row in `LoadAnnotationRows` order as `--- fragment id · date · title ---`, the summary, and a `things:` line of ids and `name (kind: note)` proposals. One call via `generate` at `RoleMap` with the resolved model (temperature 0, priority `Background`), same retry wrapper as annotation; `ParseConsolidateReply` requires a JSON object with a `things` key that unmarshals as a `mapdoc.Document`; one retry with `ConsolidateJSONRetryNudge`; still unparseable → `unparseable map reply`. Any failure from here on sets the run to `status = error` with the message (a failed run save is only logged) and leaves the document and every row untouched; the rows stay unconsolidated, so the next due tick retries. A context cancelled mid-call ends here too, with the run at `error`.
4. `finishDocument(prev, next, rows, cites)` post-processes the model's document in place: `relationships` non-nil; for every thing — a missing `id` gets one minted and counts as an `admit`, `kind` normalised, `aliases` non-nil, `fragments`/`first_seen`/`last_seen`/`exemplar_ids` reset; every thing id present in `prev` and absent from `next` counts as a `merge` (no tombstone, no alias check — an id the model dropped is simply gone, whatever it did with the name). Relationships are re-resolved end by end with `Document.Resolve` (id, else exact normalised name or alias) and dropped when either end is unresolvable, both ends resolve to the same thing, or the `(from, to, kind)` triple repeats; the surviving ends are rewritten to ids and `kind` is kept verbatim. Then, for every row and every citation in it (`ref`, else `name`), the resolved thing gets `fragments` incremented once per row, `first_seen`/`last_seen` widened from the row's date (rows with an empty date do not move them), and the row's fragment id appended to `exemplar_ids` while it holds fewer than 5. `name`, `blurb`, `aliases` and `narrative` are taken from the model as-is; a thing the model returned with an id that did not exist before is kept under that id and counts as neither admit nor merge.
5. In one transaction: `version` = loaded version + 1, `consolidated_at = now`, `body` = the finished document; each `pending` row (the set captured before step 1, not rows created since) gets `consolidated_at = now`.
6. Run set to `done` with `admits`, `merges`, `version_after` = loaded version + 1 (a failed run save is only logged; the document change stands and the run stays `running`).

Consolidation is a whole-document rewrite: the model returns the entire map every time. Citations in rows that no longer resolve stop counting; the rows themselves are never edited or re-annotated. A run row left at `running` means the process died between steps 2 and 6, or the error write in step 3 or the done write in step 6 itself failed; nothing sweeps it, and the map status reports it as interrupted (§ 6). There is no lock between annotation and consolidation: a row created after `pending` is captured but before step 1 loads all rows is included in the prompt and left unconsolidated, so it is sent again next time; one created after step 1 is simply not seen until the next run.

## 4. Reads exposed to other packages

The worker package exports no readers; every read of the map by another package goes through `internal/sourcedata/map.go` (read-only, no writes) or the plain types in `internal/mapdoc`.

- `sourcedata.FindMapRecord(app)` → the first `kalaidoscope_map` row or nil. Callers: `mapping.loadDocument`, `sourcedata.LoadMapDocument`.
- `sourcedata.LoadMapDocument(app)` → `(*mapdoc.Document, version, error)`; never creates the row (§ 1). Callers: `colour` (the settle hook and thing matching), `explore.PrepareLLMPrompt` (summaries digest), `llmcontext.hydrateSummaries`, `status.Evaluate`.
- `sourcedata.LoadAnnotationRows(app)` → every `fragment_annotation` row as `Row` (alias of `prompts.AnnotationRow`: `{FragmentID, Date, Title, Summary, Things}`), loaded in `created` order and then stably sorted by `Date` ascending (`SortRowsByDate`, exported but called only here). `Date` is the fragment's `occurred_at` day (`2006-01-02`) when the fragment is live (`deleted_at = ''`) and has a non-zero `occurred_at` (`sourcedata.FragmentDates`), else `""` — so rows of soft-deleted fragments are included and sort first. A `things` field that fails to unmarshal becomes nil rather than an error. Callers: `mapping.consolidate`, `llmcontext.hydrateSummaries`, `sourcedata.LoadMapIndex`.
- `sourcedata.IndexRows(doc, rows)` → map of thing id → indexes (into `rows`) of the rows citing it (`ref`, else `name`, resolved with `Document.Resolve`), each row counted once per thing; a nil document yields an empty index. Called only by `LoadMapIndex`.
- `sourcedata.LoadMapIndex(app)` → `MapIndex{Doc, Version, Rows, ByThing}` = the three reads above in one call. Callers: `colour.loadIndex`, `mapreader.New` (the shared read surface, `tool-loop.md`).
- `sourcedata.ResolveRef(doc, ref)` → `Document.Resolve` with a nil-document guard. No caller outside its own file.
- `internal/mapdoc` exposes the plain types (`Thing`, `Relationship`, `Document`, `Kinds`), `Parse`, `MintID`, `NormalizeKind`, `NormalizeName` (lower-cased, trimmed, inner whitespace collapsed, trailing punctuation stripped), `Document.Find` (exact id), `Document.FindByName` (first thing whose normalised name or any normalised alias equals the normalised ref; an empty normalised ref resolves to nothing) and `Document.Resolve` (`Find`, else `FindByName`). It has no database access. Consumers outside `mapping` and `sourcedata`: `prompts`, `colour`, `discover`, `mapreader`.
- In-flight flags on the worker, process memory only and reset at boot: `Annotating()`, `Consolidating()`, `WantSettle()` (true from `Signal()` until the next drain begins), `LastDrainError()`. Caller: `EvaluateStatus` (§ 6).
- Control surface on the worker: `Run(ctx)`, `Signal()`, `SignalAnnotate()`, `KickIfPending()`, `AfterDrain(fn)`, `OnSettle(fn)`, `WaitSettled()` (§§ 2–3).

## 5. The kick route

`POST /api/map` → `handlers.HandleMapKick(deps.Mapping)` → `Worker.Signal()` → **202** with no body. The handler reads nothing from the request (no body, query, or auth check of its own — the surface-wide posture is `api.md` § 1) and cannot fail. It returns nothing about the resulting drain: progress is observable as `fragment_annotation` rows and the `kalaidoscope_map` record over the realtime channel, and as the `map` axis of `GET /api/status` (§ 6). A kick while a drain is running is honoured by the following drain (§ 2).

## 6. The map status axis

`mapping.EvaluateStatus(app, worker, version, fragments)` builds the `map` object of `GET /api/status` (`api.MapStatus`; the route and the other axes are indexed in `api.md` § 9). `status.Evaluate` passes `version` from `sourcedata.LoadMapDocument` (no row is created) and `fragments` = the count of `fragment` rows with `deleted_at = ''`, and afterwards sets `thingsCount` = the number of things in that document — the one field of the object the map package does not fill. Any query error inside `EvaluateStatus` fails the whole status route with `500` `failed to evaluate status`.

**From rows:** `annotated` = count of all `fragment_annotation` rows (rows of soft-deleted fragments included); `unconsolidated` = those with `consolidated_at = ''`; `pendingAnnotation` = the pending set's size (§ 2); `lastRun` = the newest `map_run` by `created`, as `{id, status, error?, model (= generated_by_model), finished (= updated, RFC 3339 UTC), interrupted?}` — omitted when no run exists; `rounds` and `mapVersion` of the shared `RunInfo` shape are never set for a map run and so never appear; `version` as passed in.

**From in-flight flags** (all false/empty when the evaluator is given a nil worker, as a `Deps` without a manager does): `lastDrainError` (omitted when empty), `wantSettle`, and — used only for the rules below, not surfaced as fields — `Consolidating()` and `Annotating()`.

**`interrupted`** = the newest run's `status` is `running` and `Consolidating()` is false: a `running` row while no consolidation is in flight in this process is a leftover of a crash or a failed final run write (§ 3.3). Nothing changes the row; it stays interrupted until a later run supersedes it as newest.

**`state`**, the first rule that matches:

| Order | Rule | State |
|---|---|---|
| 1 | `fragments == 0` (no live fragment, whatever rows exist) | `empty` |
| 2 | `Consolidating()` | `consolidating` |
| 3 | `pendingAnnotation > 0` and `Annotating()` | `annotating` |
| 4 | `pendingAnnotation > 0` | `unannotated` |
| 5 | `unconsolidated > 0` | `folding` |
| 6 | otherwise | `settled` |

So a drain whose remaining fragments have all failed this pass (they still have no rows) reports `annotating` while it runs and `unannotated` after; an annotate drain reports `annotating` only while a fragment is still pending; unconsolidated rows report `folding` whether or not the due rule (§ 3.1) has been reached; and `settled` says nothing about `lastRun` or `lastDrainError`, which are reported alongside whatever the state is.

## 7. What the map does not do

- No re-annotation: a fragment is annotated once; an edited fragment keeps its old row, and `generated_from_map_version` is provenance only — no code reads it.
- No per-fragment integration: rows are marked `consolidated_at` only by a whole-map consolidation.
- No deletion handling: a soft-deleted fragment's row stays (only a hard delete cascades it), keeps citing things, is still sent to the consolidation prompt (undated), still counts towards `fragments` and `exemplar_ids`, and still counts in the status axis's `annotated`.
- No automatic settle for fragments that arrive outside an import: their annotate-only drain leaves the rows unconsolidated until the timer's due rule (§ 3.1) picks them up.
- No auto-map policy flag: the worker is always constructed and always runs on its signals; the only policy gate in the map's vicinity is the auto-wave gate inside the `reconcile` subscriber (§ 3.2).
- No cleanup of `map_run` rows and no recovery of one left at `running` beyond reporting it (§ 6).
- No bound on prompt size: the consolidation prompt carries every annotation row in the workspace, and the annotation prompt every thing with ≥ 2 fragments.
- No cancellation of a drain or a consolidation other than process shutdown: no route or worker interrupts one in flight; interactive work can only pre-empt an individual model call, which the retry wrapper re-enters.
