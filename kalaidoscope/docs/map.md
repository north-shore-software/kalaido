## 1. Objects

- **The document** (`kalaidoscope_map`, singleton, server-written, readable by any authenticated user): `body` is one JSON document `{things[], relationships[], narrative}`; `version` increments per consolidation; `consolidated_at` is stamped per consolidation. There are no other fields (no counters). Created with `version 0` and an empty `body` on first load by whichever reader or worker comes first (`loadDocument` takes the first row of the collection, unordered; it never checks for a second). A body that is empty, `{}`, `null`, unparseable, or lacks a `things` key parses (`mapdoc.Parse`) as an **empty** document; the parse's failure flag is discarded by every caller, so a corrupt body is indistinguishable from a fresh map.
- **A thing** (`mapdoc.Thing`): `{id, name, aliases[], kind, blurb, fragments, first_seen?, last_seen?, exemplar_ids[]}` (`first_seen`/`last_seen` are `omitempty`). `kind` ∈ `person`, `organisation`, `place`, `project`, `topic`, `other` (`mapdoc.Kinds`); `NormalizeKind` lower-cases and trims, maps `organization`/`company`/`org` to `organisation`, and anything else not in the list to `other`. Ids are minted server-side: `t_` + 8 lower-case unpadded base32 chars from 5 random bytes (a `crypto/rand` failure panics). `fragments`, `first_seen`, `last_seen`, `exemplar_ids` (≤ 5, `maxExemplars`) are recomputed at every consolidation from citations, never taken from the model.
- **A relationship**: `{from, to, kind}` by thing id.
- **An annotation row** (`fragment_annotation`, one per fragment, unique on `fragment_id`, relation with cascade delete, client-readable, server-written): `title`, `summary`, `things` (exactly the model's citations after parsing: `{ref}` or `{name, kind, note}` — a citation with both `ref` and `name` keeps only `ref`; one with neither is dropped), `decisions`/`questions`/`conclusions` (`[{text, refs[]}]`, always written, possibly `[]`; the parser drops items with empty `text` and removes blank refs), `consolidated_at` (empty until a consolidation reads the row; secondary index `idx_fragment_annotation_consolidated_at`), `generated_from_map_version` (the `kalaidoscope_map.version` whose document was in the prompt), `generated_by_model`, `created`. The row has no `updated` autodate.
- **A run** (`map_run`, server-written, client-readable, never pruned): one per consolidation attempt — `status` (`running`/`done`/`error`), `error`, `generated_by_model`, `pending_in`, `admits`, `merges`, `version_before`, `version_after`, `created`, `updated`.

## 2. Annotation (the worker drain)

**Pending set** (`pendingFragments`) = every `fragment` with `deleted_at = ''` whose id has no `fragment_annotation` row, computed by loading every annotation row and every live fragment and diffing in memory, then stably sorted: fragments with `ingested_via != "import"` first, then by `occurred_at` ascending within each group. `PendingCount` is the size of this set (§ 4).

**Two signals, one channel.** `signal` is a buffered channel of capacity 1. `SignalAnnotate()` does a non-blocking send (a wake already waiting is not duplicated). `Signal()` sets the `wantSettle` flag and then calls `SignalAnnotate()`. The worker `loop` takes, per wake: the follow-up callbacks registered so far (`followUps.Take()`, § below), then `wantSettle.Swap(false)` — so a full (settling) drain is one whose flag was set before it started. Because the channel holds one wake, several signals coalesce into one drain; a `Signal()` that lands while a drain is running leaves the flag set and a wake queued, so it is honoured by the drain *after* it, never lost. Callers: `SignalAnnotate` — every fragment create with `ingested_via != "import"` (`server.RegisterTriggers`, `ingestion.md` § 7), an async ingest completion whose config lacks `organize_after` (`ingestion.md` § 3), and `mapping.Register`'s `OnServe` hook after `se.Next()` when the pending set is non-empty (a pending-count error is swallowed and no signal is sent); `Signal` — `POST /api/map` (§ 5) and `ingest.startPipeline`, the post-import chain (`organize.md` § 8).

**Follow-ups.** `AfterDrain(fn func(err error))` appends a one-shot callback to a `followup.Queue`. Each drain runs only the callbacks that were queued *before* it began, after the drain (and its settle cycle, if any) completes, with the drain's first error; a callback added mid-drain runs after the next drain. Nothing in this package ever calls `Signal` on behalf of a queued callback — the caller does. The sole registrant is `ingest.startPipeline`, which queues a callback and then itself calls `mapping.Signal()`; the callback, on a nil error, calls `discover.Signal` for `colours`, `projections`, `reflections` in that order, and on a non-nil error returns without signalling discover (`organize.md` § 8).

**The drain.** `drain(app, full)` resolves `llm.RoleAnnotate` once (`llm.ResolveRole`; a resolution failure returns immediately — no fragments, no settle cycle even for a full drain, and the error becomes `LastDrainError`). Then it loops: recompute the pending set, drop fragments already marked failed in this drain, stop when nothing remains. Within an iteration up to 100 (`annotateWorkers`) fragments are annotated concurrently through a semaphore; the dispatch loop stops handing out fragments once any goroutine has returned `usage.ErrExhausted`, waits for in-flight ones, and then breaks out of the outer loop too. Each `annotateOne`:

1. Loads the document (`loadDocument`, fresh per fragment — a later fragment in the same drain sees things admitted by a consolidation that landed meanwhile) and records its `version`.
2. Builds one user message: `prompts.AnnotatePrompt(doc, prompts.FragmentBlock(type, source, id, content))`. The map block lists only things with `fragments >= 2` (`annotateInlineFloor`), relationships whose both ends are among the listed things, and the narrative; a map with no listed things and an empty narrative gets the one-line `annotateEmptyMap` notice instead. Things with fewer than 2 citing fragments are invisible to the annotator.
3. One call via `usage.GenerateOnceMsgs` at `RoleAnnotate` with the resolved model (registry options: temperature 0; scheduler priority `Background`, `llm-queue-quota.md` § 2.1), wrapped in `retryPreempted`: `llmq.ErrPreempted` retries without limit; a `llm.ProviderError` of kind `Quota` or `Transient` retries up to 6 more times (`maxThrottledAttempts`); any other error — including `usage.ErrExhausted` from the period quota, which is not a `ProviderError` — returns at once.
4. `prompts.ParseAnnotateReply`: takes the text between the first `{` and the last `}`, requires it to be a JSON object with a `summary` key, and requires a non-empty trimmed `summary`. On failure the conversation is extended with the assistant reply and `prompts.MapJSONRetryNudge` and the call is made **once** more; still unparseable → error `unparseable annotate reply`.
5. Creates the `fragment_annotation` row: `fragment_id`, `title`, `summary`, the four JSON fields, `generated_from_map_version` = the version loaded in step 1, `generated_by_model` = the resolved model. `consolidated_at` is left empty.

A failure is logged, marks the fragment failed for the rest of this drain (it is retried on the next signal), and — if first — becomes the drain's error. After the loop, a full drain runs one **cycle** (§ 3.2) — even when the loop ended on quota exhaustion or annotated nothing; an annotate-only drain ends here and leaves the rows for the aggregate loop. `Annotating()` reports true from before `drain` starts until it returns, so it also covers a full drain's settle cycle. `LastDrainError` is set to the drain's first error message, or cleared by an error-free drain; the same error is passed to the follow-ups.

## 3. Aggregation

### 3.1 When consolidation is due

`aggregateLoop` ticks every 10 s (`aggregateTick`, `time.Tick`, first tick 10 s after `Register`). Each tick, `consolidateDue` queries `fragment_annotation` rows with `consolidated_at = ''`, newest `created` first: a query error is logged and the tick skipped; no rows → not due; more than 50 rows (`consolidatePendingFloor`) → due; otherwise due when the newest such row's `created` is more than 1 minute old (`consolidateStaleAge`). When due the tick runs a **cycle** (§ 3.2). When not due the tick does nothing. Boot does not itself trigger a consolidation; the first tick does if rows qualify. The due rule is the only thing the aggregate loop evaluates — it does not look at the pending set, at `Annotating()`, or at the document.

### 3.2 A cycle

`cycle(app)` = `integrate(app)` followed by every registered settle hook, in registration order, outside the mutex. `integrate` takes `aggregateMu`, sets `Consolidating()` true, runs `consolidate` (§ 3.3, error logged and dropped), clears the flag and releases the mutex — so `Consolidating()` is true for the whole of `integrate`, including a `consolidate` that finds nothing to do. Two cycles can be requested at once (a full drain's settle and an aggregate tick); the mutex serialises their `integrate` phases, and the second typically finds no unconsolidated rows and returns without a run row — its settle hooks still run.

**Settle hooks (emitting side).** `OnSettle(fn func(core.App))` appends to a package-level slice with no locking; every hook runs after every cycle regardless of whether the consolidation did anything, succeeded, or failed. Hooks run synchronously on the calling goroutine — inside a full drain (so before its follow-ups and before `Annotating()` clears) or inside the aggregate tick. Subscribers, registered in `server.New` immediately after `mapping.Register`, in this order:

1. `colour.OnMapSettled` — reads the document's version and the annotation row count, and recomputes thing-backed colour membership only when either changed since the last settle it saw (`colours.md` § 3).
2. `reconcile.OnMapSettled` — calls `reconcile.EnqueueWave()`, which is a no-op unless the auto-wave policy is on (`rotation.md` § 3, `organize.md` § 7).

`WaitSettled()` locks and immediately unlocks `aggregateMu`: it blocks while an `integrate` is in progress and returns once it is not. It does not wait for the settle hooks, for an in-progress annotation drain, or for a consolidation that is *due* but not yet started. Its one caller is `discover.Run` (`discover.md` § 2).

### 3.3 Consolidation

`consolidate` returns nil at once when no `fragment_annotation` row has `consolidated_at = ''` (this is the silent skip). Otherwise, with `pending` = those rows (oldest `created` first):

1. Loads **all** annotation rows via `LoadRows` (§ 4) — consolidated and unconsolidated alike — and the current document; resolves `llm.RoleMap` (a failure here returns before any run row is written).
2. Creates a `map_run` with `status = running`, `generated_by_model`, `pending_in` = len(`pending`), `version_before` = the loaded version. A failure to save the run aborts the consolidation.
3. One user message: `prompts.ConsolidatePrompt(doc, rows)` — the current map as JSON of `{things[{id,name,aliases,kind,blurb}], relationships, narrative}` (counts and dates omitted), or the first-run notice when the map has no things and no narrative; then **every** row in `LoadRows` order as `--- fragment id · date · title ---`, the summary, and a `things:` line of ids and `name (kind: note)` proposals. One call via `generate` at `RoleMap` with the resolved model (temperature 0, priority `Background`), same retry wrapper as annotation; `ParseConsolidateReply` requires a JSON object with a `things` key; one retry with `ConsolidateJSONRetryNudge`; still unparseable → `unparseable map reply`. Any failure from here on sets the run to `status = error` with the message (a failed run save is only logged) and leaves the document and every row untouched; the rows stay unconsolidated, so the next due tick retries.
4. `finishDocument(prev, next, rows, cites)` post-processes the model's document in place: `relationships` non-nil; for every thing — a missing `id` gets one minted and counts as an `admit`, `kind` normalised, `aliases` non-nil, `fragments`/`first_seen`/`last_seen`/`exemplar_ids` reset; every thing id present in `prev` and absent from `next` counts as a `merge` (no tombstone, no alias check — an id the model dropped is simply gone, whatever it did with the name). Relationships are re-resolved end by end with `ResolveRef` (id, else exact normalised name or alias) and dropped when either end is unresolvable, both ends resolve to the same thing, or the `(from, to, kind)` triple repeats; the surviving ends are rewritten to ids. Then, for every row and every citation in it (`ref`, else `name`), the resolved thing gets `fragments` incremented once per row, `first_seen`/`last_seen` widened from the row's date (rows with an empty date do not move them), and the row's fragment id appended to `exemplar_ids` while it holds fewer than 5. `narrative` and `blurb` are taken from the model as-is; a thing the model returned with an id that did not exist before is kept under that id and counts as neither admit nor merge.
5. In one transaction: `version` = loaded version + 1, `consolidated_at = now`, `body` = the finished document; each `pending` row (the set captured before step 1, not rows created since) gets `consolidated_at = now`.
6. Run set to `done` with `admits`, `merges`, `version_after` = loaded version + 1 (a failed run save is only logged; the document change stands).

Consolidation is a whole-document rewrite: the model returns the entire map every time. Citations in rows that no longer resolve stop counting; the rows themselves are never edited or re-annotated. A run row left at `running` means the process died between steps 2 and 6, or the error write in step 3 itself failed; nothing sweeps it, and the organise status reports it as interrupted (`organize.md` § 3). There is no lock between annotation and consolidation: a row created after `pending` is captured but before step 1 loads all rows is included in the prompt and left unconsolidated, so it is sent again next time; one created after step 1 is simply not seen until the next run.

## 4. Reads exposed to other packages

- `LoadDocument(app)` → `(*mapdoc.Document, version, error)`; creates the singleton at `version 0` if absent (§ 1). Callers: `discover.newContext`, `colour` (match/rematch), `llmcontext` summaries, `chat`, `organize.Evaluate`.
- `LoadRows(app)` → every `fragment_annotation` row as `Row` (alias of `prompts.AnnotationRow`: `{FragmentID, Date, Title, Summary, Things}`), loaded in `created` order and then stably sorted by `Date` ascending. `Date` is the fragment's `occurred_at` day (`2006-01-02`) when the fragment is live (`deleted_at = ''`) and has a non-zero `occurred_at`, else `""` — so rows of soft-deleted fragments are included and sort first. A `things` field that fails to unmarshal becomes nil rather than an error. Callers: `consolidate`, `discover`, `colour`, `llmcontext` summaries.
- `ResolveRef(doc, ref)` → a thing by exact id (`Document.Find`), else the first thing whose normalised name or any normalised alias equals the normalised ref (lower-cased, trimmed, inner whitespace collapsed, trailing punctuation stripped); an empty normalised ref resolves to nothing. Callers: `finishDocument`, `IndexRows`, `discover`, `colour`.
- `IndexRows(doc, rows)` → map of thing id → indexes (into `rows`) of the rows citing it, each row counted once per thing. Callers: `discover.newContext`, `colour.loadIndex`.
- `PendingCount(app)` → the size of the pending set (§ 2), computed by the same full load and diff. Caller: `organize.evaluateMap`.
- In-flight flags, process memory only and reset at boot: `Annotating()`, `Consolidating()`, `LastDrainError()`. Caller: `organize.evaluateMap`.
- Control surface: `Register(app)` (starts both goroutines, binds the boot signal), `Signal()`, `SignalAnnotate()`, `AfterDrain(fn)`, `OnSettle(fn)`, `WaitSettled()`.
- `internal/mapdoc` exposes the plain types (`Thing`, `Relationship`, `Document`, `Kinds`), `Parse`, `Document.Find`, and `NormalizeKind`; it has no database access. Its other consumer is `internal/prompts`.

## 5. The kick route

`POST /api/map` → `handlers.HandleMapKick` → `mapping.Signal()` → **202** with no body. The handler reads nothing from the request (no body, query, or auth check of its own — the surface-wide posture is `api.md` § 1) and cannot fail. It returns nothing about the resulting drain: progress is observable as `fragment_annotation` rows and the `kalaidoscope_map` record over the realtime channel, and as the map axis of `GET /api/organize` (`organize.md` § 3). A kick while a drain is running is honoured by the following drain (§ 2).

## 6. What the map does not do

- No re-annotation: a fragment is annotated once; an edited fragment keeps its old row, and `generated_from_map_version` is provenance only — no code reads it.
- No per-fragment integration: rows are marked `consolidated_at` only by a whole-map consolidation.
- No deletion handling: a soft-deleted fragment's row stays (only a hard delete cascades it), keeps citing things, is still sent to the consolidation prompt (undated), and still counts towards `fragments` and `exemplar_ids`.
- No automatic settle for fragments that arrive outside an import: their annotate-only drain leaves the rows unconsolidated until the aggregate loop's due rule (§ 3.1) picks them up.
- No auto-map policy flag: the worker is always registered and always runs on its signals; the only policy gate in the map's vicinity is the auto-wave gate inside the `reconcile` subscriber (§ 3.2).
- No cleanup of `map_run` rows and no recovery of one left at `running`.
- No bound on prompt size: the consolidation prompt carries every annotation row in the workspace, and the annotation prompt every thing with ≥ 2 fragments.
