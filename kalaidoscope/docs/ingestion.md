## 2. Sync path

Body bound as `api.IngestMessage` with `BindBody`; JSON keys are **lowerCamelCase**: `type`, `ingestedVia`, `source`, `content`, `occurredAt`, `format`, `fragmentLimit`, `extensions`, `skipDuplicates`. The type's `UnmarshalJSON` also accepts the legacy snake_case keys `ingested_via`, `occurred_at`, `fragment_limit`, `skip_duplicates` (when a body carries both spellings the lowerCamelCase one wins; `type`, `source`, `content`, `format`, `extensions` have one spelling). Rejections, in order: a body that fails to bind → `400 invalid request body` (a body with `Content-Length: 0` binds nothing and falls through to the next check); `content` empty after trimming → `400 content required`; `format` non-empty, `fragmentLimit` non-zero (negative included) or `extensions` non-empty → `400 format, fragmentLimit and extensions apply to file ingest only`. Then `ingest.IngestSingle`: a writer with limit 0 and dedupe per `skipDuplicates` (which on this path preloads every existing fragment's hash per call, § 6); `ingestedVia` trimmed, default `"sync"` (a value outside `import|app|sync` fails record validation → `500 ingest failed`); `type` trimmed, default `"note"` (outside `email|note|chat|edit` → `500`); `source` stored untrimmed; `occurredAt` parsed as RFC3339 and **silently dropped** when it does not parse (the birth hook then sets now). The writer's batch size is 1, so the fragment is committed in its own transaction and the birth hooks (§ 7) fire before the response. Any writer error → `500 ingest failed`. Response `200 {fragmentId, ingested}`; a deduped entry returns `fragmentId: ""`, `ingested: 0` with `200` (the only way `fragmentId` is empty, since empty content was already rejected). The handler logs one line per outcome (`ingested fragment` / `duplicate entry skipped`) with a 120-rune whitespace-collapsed preview of the content.

A sync body that names `ingestedVia = "import"` is accepted: that fragment gets only the colour signal at birth (§ 7) and no completion handoff follows, because none exists on this path.

## 3. Async batch path

`OnRecordCreate("ingest")` (`ingest.RegisterHooks`, bound from `RegisterTriggers` with `ingest.Deps{Mapping, Reconcile, Discover, Runner}`) runs **before** the record is saved. No non-test code creates `ingest` rows programmatically, so this is always the collection's create endpoint. It reads the unsaved uploads from the `file` field (max 50 files, 200 MiB each) into memory in order, **stopping at the first upload that cannot be opened or read** — the failure is logged (`read uploads failed`), uploads before it are kept, the failing and later uploads are never parsed, and processing continues; reads `format`, `fragment_limit`, `extensions` (split on commas, trimmed, lower-cased, `.`-prefixed, empties dropped), `skip_duplicates`, `organize_after`; forces `status = "pending"` whatever the client sent; then lets the save proceed (`format` is a select field `zip|mbox|docx|text`, so any other value fails record validation and the create returns `400` with no goroutine started; a negative `fragment_limit` behaves as 0, unlimited; a save failure is returned and no goroutine starts). `ingested` and `error` are client-writable at create and stand as sent until completion overwrites them. After the save, `deps.Runner.Go(processIngestRecord)` starts the work on the server's `workerutil.TrackedRunner`: its own goroutine, under the runtime context that shutdown cancels, counted so shutdown waits for it (bounded by the 10 s grace, `boot-and-workers.md` § 3). Only the row id, the config and the in-memory bytes are handed over; the row itself is re-read at the end.

The goroutine parses each file in order with **one writer per file** (origin `import`, batch 100, § 6), so `fragment_limit` applies **per file** and the dedupe set is preloaded again per file (the preload reads the database, so it sees fragments written by earlier files). Fragments flushed before a file's error are counted and kept; the first file error is logged (`processing file failed`) and stops processing of later files. It then reloads the `ingest` row and sets `ingested` (total fragments written) and `status = "done"`, or `status = "error"` + `error` (the error text). A reload failure is logged (`reload record failed`) and **returns immediately**: the row stays `pending` (until the next boot's sweep, below), and none of the completion signals fire. A save failure of the status is logged (`save status failed`) and the signals still fire. One `completed record` line is logged with the fragment and file counts. Then, **regardless of whether the import errored or wrote anything**:

- `ingested > 0`: `Reconcile.EnqueueWave()` — one debounced request for a speculative generation wave; a no-op unless `KALAIDO_AUTO_WAVE` is set (`reconcile.md` § 4).
- `organize_after` set: the post-import pipeline is started (§ 8) and nothing else is signalled here.
- otherwise `Mapping.SignalAnnotate()` — a coalescing wake of the mapping worker for an annotate-only drain (`map.md` § 2). Import-origin fragments do not signal annotation at birth (§ 7), so this is the only annotate wake an import without `organize_after` produces.

**Shutdown.** Cancelling the runner context makes the parsers return `context.Canceled` at their next check (text and docx before emitting, mbox per line, zip per entry); `run` first flushes the page in hand, then reports the cancellation as the file's error, so — when the reload and save still complete before the process exits — the row ends `status = "error"`, `error = "context canceled"`, with the fragments committed so far counted.

**Crash leftovers.** `ingest.SweepPending(app)` runs in `OnServe` before the listener binds (`boot-and-workers.md` § 1): every `ingest` row with `status = "pending"` is set to `status = "error"`, `error = "server restarted while processing"` (`ingested` untouched); a lookup failure is logged and the sweep does nothing; a per-row save failure is logged; a non-zero count is logged as a warning. No signal fires for swept rows.

## 5. Parsers

`parsers.Parse(ctx, src, exts, emit)` dispatches on `src.Format` when set (`zip`, `mbox`, `docx`; anything else, including unknown strings, is `text`), else infers from the file name's extension (lower-cased): `.mbox`, `.eml` → `mbox`; `.zip` → `zip`; `.docx` → `docx`; anything else → `text`. The `format` override applies to the uploaded file only; entries inside a zip always infer from their own name. Every parser emits `parsers.Fragment{Type, Source, Content, SourceTime}`; a zero `SourceTime` means unknown. No parser converts character sets: bytes are passed through as they are.

| Format | Behaviour |
|---|---|
| `text` | One `note` fragment holding the whole payload; source = file name, or `imported text` when the name is blank. |
| `docx` | Opens the payload as a zip (`invalid docx archive` error otherwise), reads `word/document.xml` (`not a docx: word/document.xml missing` error otherwise; an open or read error of that entry is the file's error) and walks its XML tokens: character data inside `<t>` elements is kept, `<tab>` → tab, `<br>`/`<cr>` → newline, `</p>` → newline; a malformed token stream stops the walk silently, keeping what was read; the result is trimmed. One `note` fragment; source = file name or `imported document`. |
| `mbox` | Reads the payload line by line (1 MiB buffer). A line starting with `From ` ends the current message (emitted if non-empty) and is itself dropped; any other line is appended after unquoting — a line of one or more `>` immediately followed by `From ` loses one leading `>`. A payload with no `From ` line at all is one message; consecutive `From ` lines produce nothing between them; the last message is emitted at end of input. Each message goes to `net/mail`; an unparseable message becomes a fragment holding the raw text (type `email`, source `imported email`, no time). Otherwise `From`/`To`/`Subject` are RFC 2047-decoded (left as-is when decoding fails), `Date` is taken raw and trimmed, and the body is extracted (below). Content = each non-empty header as `Label: value` on its own line, a blank line, then the body. Source = `from · subject`, whichever parts are non-empty, else `imported email`. `SourceTime` = the parsed `Date` header; a parse failure leaves it zero. Type `email`. The context is checked before every line. |
| `zip` | Opens the payload as a zip (`invalid zip archive` error otherwise). Every non-directory entry whose lower-cased name ends with one of `exts` (the batch path always passes a non-empty list: the record's `extensions`, else `.txt`, `.md`, `.docx`) is read fully (read errors ignored, partial bytes used) and recursively parsed with format inferred from the entry name — so a nested `.zip`, `.mbox` or `.eml` is parsed when its extension is listed. An entry that cannot be opened is logged (`skipping unreadable zip entry`) and skipped. An error from any entry's parser aborts the whole zip. The context is checked before every entry. |

**Email body extraction** (`extractText`): an unparseable or empty `Content-Type` → the body decoded per `Content-Transfer-Encoding`. `multipart/*` without a `boundary` → the raw body undecoded; with one → each part is extracted recursively and the first `text/plain` part with non-empty text is returned, else the first part of any kind with non-empty text (a nested multipart counts through its own result), else `""`; a malformed part stream ends the walk with what was found. A single `text/*` part → decoded body. Any other single part (an attachment) → `""`. Decoding handles `quoted-printable` and `base64` (standard alphabet); anything else is read raw. Read and decode errors are swallowed and yield whatever bytes were read.

`fragment_limit` stops parsing through a sentinel error (`errBudget`) returned by the sink once the writer is full — checked before each emit, so exactly `limit` fragments are built; that stop is not reported as an error and the file ends `done` with a truncated count. A cancelled context **is** reported as an error (§ 3). Every other parser error is the file's error.

## 6. The writer

`newWriter(app, limit, skipDuplicates)`: fails when the `fragment` collection cannot be found. With dedupe on, it preloads the SHA-256 of **every** existing fragment's content (soft-deleted ones included) into memory; a preload failure is logged and dedupe proceeds with an empty set. `limit = 0` means unlimited. The writer commits in pages: `batch = 1` by default (the sync path), `importBatch = 100` on the batch path; built records wait in `pending` until a page is full. `addAt(type, source, content, sourceTime)`: trims content; empty → skipped silently; hash already seen → skipped silently (the hash is recorded when the record is built, so repeats within one file are also dropped, and a page that later fails to commit leaves its hashes in the set); otherwise a `fragment` record is built with `type`, `ingested_via` (the writer's origin), `source`, `content`, and `occurred_at` when `sourceTime` is non-zero (a `ParseDateTime` failure drops it silently), appended to `pending`, and the page is flushed once it holds `batch` records. `full()` is `limit > 0 && count + len(pending) >= limit`, so the limit counts records not yet committed; skipped entries count toward nothing. `flush()` saves every pending record, in order, in **one transaction**; on failure the page is dropped (`count` and `lastID` unchanged) and the error is returned to the caller; on success `count` grows by the page and `lastID` is the page's last id. `run` (batch path) flushes the tail after the parse ends, whatever ended it, and a tail-flush failure is the file's error. A save error — including record validation: `type` and `ingested_via` are select fields, `content` is required with a 100,000,000-character maximum — is returned to the caller. Inside a page's transaction `OnRecordCreate` fires per record; `OnRecordAfterCreateSuccess` fires once per record after the commit (§ 7), so the workers see a whole page at once.

## 7. Birth and delete hooks

- `OnRecordCreate("fragment")` (before save, every create path): `occurred_at` defaults to now when zero; `ingested_via` defaults to `"app"` when empty. Validation runs after these defaults.
- `OnRecordAfterCreateSuccess("fragment")` (after the create is durable — for a writer page, the bookmark path and the edit path, after their transaction commits; a rolled-back transaction fires nothing): `rt.workers.Colour.Signal()` always — a coalescing wake of the colour worker, which judges the new fragment against every prompt colour past its watermark (`colours.md` § 4). Unless `ingested_via = "import"`: `rt.workers.Mapping.SignalAnnotate()` — a coalescing wake of the mapping worker for an annotate-only drain, no map cycle (`map.md` § 2) — and `rt.workers.Reconcile.EnqueueWave()` — a debounced request for a speculative wave, a no-op unless `KALAIDO_AUTO_WAVE` is set (`reconcile.md` § 4). Imported fragments are left for the completion handoff (§ 3). No thing matching happens at birth; a new fragment joins thing-backed colours only after it is annotated and the map next settles (`colours.md` § 3).
- `OnRecordDeleteRequest("fragment")` — the collection's built-in delete endpoint only. PocketBase checks the collection rule before this hook runs, and the `fragment` delete rule is nil, so a request without superuser auth receives `403` and the hook never runs. For a superuser request: instead of deleting, sets `deleted_at = now` when it is unset and saves (a save error is returned to the request), then returns **204** without calling the next handler — the delete never executes, no `OnRecordDelete` model hook fires, and no cascade runs. A repeat request returns `204` and leaves `deleted_at` unchanged. There is no restore surface for fragments (`pbutil.Restore` is called only through `engine.Restore`, for projections and reflections), no other soft-delete route, and no code path calls `Delete` on a fragment. Consequences of a set `deleted_at`: its `colour_fragment` and `fragment_annotation` rows remain (they cascade only on a hard delete, `schema.md` § 5), and a `chat_message.fragment_id` pointing at it is kept; it is excluded by the live filter `deleted_at = ''` (`schema.NotDeleted()`) from context resolution (`llmcontext` resolve, `context.md` § 2), the map's pending set (`sourcedata.PendingAnnotationFragments`) and the consolidation date table (`sourcedata.FragmentDates` — its annotation row still participates in consolidation, without a date; `map.md` § 2, § 3), the colour worker's watermark paging and the colour preview sample (`colours.md` § 4, § 5), the `view_stream` view (`schema.md` § 2.17), the `fragments` count of `GET /api/status`, and bookmark reuse (a bookmark whose fragment is soft-deleted is re-saved as a new fragment, § 1). It is still returned by loads by id (`sourcedata.FindFragmentsByIDs`, reached through `llmcontext.LoadFragmentsByIDs`: hydration of an already-pinned receipt's `fragmentIds`, summaries-mode seeding rows, the `read_fragment` tool of the map reader (`tool-loop.md` § 7.4), colour manual-example blocks in the worker and the preview), by the colour worker's watermark lookup, and is still seen by the dedupe preload.

## 8. The post-import pipeline

`ingest.startPipeline(deps)` is the only registrant of a mapping follow-up in the tree. It does two things, in this order: `Mapping.AfterDrain(fn)` — appends a one-shot `func(error)` to the mapping worker's `workerutil.Callbacks` — then `Mapping.Signal()` — sets the worker's `wantSettle` flag and notifies its coalescing signal (a buffered channel of one; a notify while one is already pending is absorbed).

The mapping annotate loop, on each wake, first **detaches** every callback registered so far, then consumes `wantSettle` (`Swap(false)`), then drains; with the flag set the drain is **full**: annotate every pending fragment, then one map cycle (consolidate, then the settle hooks — `map.md` § 3.2). When the drain returns, the detached callbacks are invoked with its error. Consequences:

- The callback runs after a full drain that began after the import completed. If no drain is in progress, the notify wakes the loop at once. If one is in progress, the notify stays pending and `wantSettle` stays set until the current drain ends; the next drain then detaches the callback, reads the flag, and runs full. The in-progress drain's own outcome does not reach the callback.
- The drain's error is its **first annotate failure** (a fragment that fails is skipped for the rest of that drain; a quota-exhaustion failure also ends the drain early), a role-resolution or pending-list failure, or `context.Canceled`; a consolidation failure is logged inside the cycle and is **not** part of it. The map cycle is skipped when the context is already cancelled.
- On a nil error the callback calls `Discover.Signal("colours")`, `Discover.Signal("projections")`, `Discover.Signal("reflections")`: each marks the kind pending and wakes the discover worker, which on its next wake takes every pending kind in pipeline order `colours → projections → reflections` and runs them one after another (`discover.md` § 2). On a non-nil error the callback does **nothing**: no discover kind is signalled, nothing is retried, and nothing records that the pipeline was dropped — the drain error itself is visible only as the map worker's last drain error.
- The pipeline starts whenever `organize_after` is set — after an errored import and after an import that wrote nothing alike (§ 3). `Reconcile.EnqueueWave()` (when anything was written) precedes it; `Mapping.SignalAnnotate()` is not called separately, since `Signal()` includes the annotate wake.

## 9. The imports status axis

`ingest.EvaluateStatus(app)` returns `api.ImportsStatus{pending, lastError?}`, composed by `internal/status` into the `imports` object of `GET /api/status` (`api.md` § 9). `pending` = the count of `ingest` rows with `status = "pending"`. `lastError` = the `error` text of the newest-`created` row with `status = "error"` (`FindRecordsByFilter("status = 'error'", "-created", 1, 0)`); the key is omitted (`omitempty`) when no such row exists or its `error` is empty. The axis reads rows only — neither the runner nor any in-process flag is consulted — so a row counts as pending from its create until its goroutine's final save (§ 3), or until the boot sweep marks it `error`; a row whose reload failed stays counted until that sweep. A finished (`done`) import does not clear `lastError`, and nothing ever resets an `error` row (the collection's update endpoint is superuser-only), so `lastError` reports the most recently created failed import for the life of the database. Either query failing fails the whole status route with `500`. The `fragments` count in the same response (live fragments, `deleted_at = ''`) is computed by `internal/status`, not by this package.
