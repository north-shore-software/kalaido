## 1. Entry paths

1. **Sync single entry** — `POST /api/ingest` (no auth middleware; the integration test posts anonymously): one fragment per call, written inline through the writer, `ingested_via` = the body's `ingested_via` or `"sync"` when empty.
2. **Async batch** — creating an `ingest` record through the collection's built-in create endpoint (create rule `@request.auth.id != ''`; update and delete are superuser-only) with file uploads: parsed in a background goroutine through the writer, `ingested_via = "import"`.
3. **Bookmark save** — `POST /api/chat/conversations/{cid}/bookmarks/save` (`api.md` § 4): every bookmarked, non-system turn of the conversation with non-empty text becomes a `type = "chat"` fragment (a row whose stored message fails to decode is skipped silently), created directly (not through the writer) inside one transaction; `ingested_via = "app"`, `source = "chat:<external_conversation_id>:<message id>"`, `occurred_at` = the `chat_message` row's `created`; the row is stamped with `fragment_id`. A row already pointing at a fragment whose `deleted_at` is empty is reused, not recreated. No dedupe, no limit.
4. **Hand edit** — `POST /api/projections/{id}/candidates/{rid}/edit` (`api.md` § 5): one `type = "edit"` fragment per accepted edit, created directly inside the edit transaction; `ingested_via = "app"`, `source = edit to projection "<name>" (candidate <id>)`, `content` = `prompts.EditFragmentContent(oldText, newText)` (a fixed sentence, then `Before:` and `After:` passages each fenced by `<<<` / `>>>` lines), `occurred_at = now`. The fragment id is appended to the parent's `current_context_spec.fragmentIds` and to the new snapshot's spec and receipt. No dedupe, no limit.

The `fragment` collection's own create endpoint is superuser-only (`DisableWriteOperations` → nil create rule); no code path creates `fragment` records any other way. A fragment created by a superuser through that endpoint takes the birth defaults of § 7 (`ingested_via = "app"`).

## 2. Sync path

Body bound as `api.IngestMessage` (**snake_case**): `type`, `ingested_via`, `source`, `content`, `occurred_at`, `format`, `fragment_limit`, `extensions`, `skip_duplicates`. A body that fails to bind → `400 invalid request body`; `content` empty after trimming → `400 content required`. Then: `ingested_via` trimmed, default `"sync"` (a value outside `import|app|sync` fails record validation → `500`); `type` trimmed, default `"note"` (outside `email|note|chat|edit` → `500`); `source` stored untrimmed; `occurred_at` parsed as RFC3339 and **silently dropped** when it does not parse (the birth hook then sets now); `skip_duplicates` enables the writer's dedupe (§ 6), which on this path preloads every existing fragment's hash per call. `format`, `fragment_limit`, `extensions` are accepted and unused on this path (the writer is built with limit 0). Any writer error → `500 ingest failed`. Response `200 {fragmentId, ingested}`; a deduped entry returns `fragmentId: ""`, `ingested: 0` with `200` (the only way `fragmentId` is empty, since empty content was already rejected). The handler logs one line per outcome with a 120-rune preview of the content.

## 3. Async batch path

`OnRecordCreate("ingest")` runs **before** the record is saved (there is no programmatic creator of `ingest` rows, so this is always the collection's create endpoint): it reads the unsaved uploads from the `file` field (max 50 files, 200 MiB each) into memory in order, **stopping at the first upload that cannot be opened or read** — the failure is logged, uploads before it are kept, the failing and later uploads are still stored on the row but never parsed, and processing continues; reads `format`, `fragment_limit`, `extensions` (split on commas, trimmed, lower-cased, `.`-prefixed, empties dropped), `skip_duplicates`, `organize_after`; forces `status = "pending"` whatever the client sent; `format` is a select field (`zip|mbox|docx|text`), so any other value fails record validation and the create returns `400` with no goroutine started, and a negative `fragment_limit` behaves as 0 (unlimited); lets the save proceed (a save failure is returned and no goroutine starts); then starts `processIngestRecord` in a goroutine with the row id, the config and the in-memory bytes. `ingested` and `error` are client-writable at create and stand as sent until completion overwrites them.

The goroutine (`context.Background()`, never cancelled) parses each file in order with **one writer per file**, so `fragment_limit` applies **per file** and the dedupe set is preloaded again per file (the preload reads the database, so it sees fragments written by earlier files). Fragments written before a file's error are counted and kept; the first file error stops processing of later files. It then reloads the `ingest` row and sets `ingested` (total fragments written), `status = "done"`, or `status = "error"` + `error` (the error text). A reload failure is logged and **returns immediately**: the row stays `pending` forever, and none of the completion signals below fire. A save failure of the status is logged and the signals still fire. Then, **regardless of whether the import errored**:

- `ingested > 0`: `reconcile.EnqueueWave()` — one debounced request for a speculative generation wave; a no-op unless `KALAIDO_AUTO_WAVE` is set (`rotation.md` § 3).
- `organize_after` set: the post-import chain is started (`organize.md` § 8) — a follow-up registered on the mapping worker, then `mapping.Signal()` (a full drain ending in a map cycle) and, on a clean drain, `discover.Signal` for `colours`, `projections`, `reflections`.
- otherwise `mapping.SignalAnnotate()` — a coalescing wake of the mapping worker for an annotate-only drain (`map.md` § 2). Import-origin fragments do not signal annotation at birth (§ 7), so this is the only annotate wake an import without `organize_after` produces.

## 5. Parsers

`parsers.Parse(ctx, src, exts, emit)` dispatches on `src.Format` when set (`zip`, `mbox`, `docx`; anything else, including unknown strings, is `text`), else infers from the file name's extension (lower-cased): `.mbox`, `.eml` → `mbox`; `.zip` → `zip`; `.docx` → `docx`; anything else → `text`. The `format` override applies to the uploaded file only; entries inside a zip always infer from their own name. Every parser emits `parsers.Fragment{Type, Source, Content, SourceTime}`; a zero `SourceTime` means unknown. No parser converts character sets: bytes are passed through as they are.

| Format | Behaviour |
|---|---|
| `text` | One `note` fragment holding the whole payload; source = file name, or `imported text` when the name is blank. |
| `docx` | Opens the payload as a zip (`invalid docx archive` error otherwise), reads `word/document.xml` (`not a docx: word/document.xml missing` error otherwise) and walks its XML tokens: character data inside `<t>` elements is kept, `<tab>` → tab, `<br>`/`<cr>` → newline, `</p>` → newline; a malformed token stream stops the walk silently, keeping what was read; the result is trimmed. One `note` fragment; source = file name or `imported document`. |
| `mbox` | Reads the payload line by line. A line starting with `From ` ends the current message (emitted if non-empty) and is itself dropped; any other line is appended after unquoting — a line of one or more `>` immediately followed by `From ` loses one leading `>`. A payload with no `From ` line at all is one message; consecutive `From ` lines produce nothing between them. Each message goes to `net/mail`; an unparseable message becomes a fragment holding the raw text (type `email`, source `imported email`, no time). Otherwise `From`/`To`/`Subject` are RFC 2047-decoded (left as-is when decoding fails), `Date` is taken raw, and the body is extracted (below). Content = each non-empty header as `Label: value` on its own line, a blank line, then the body. Source = `from · subject`, whichever parts are non-empty, else `imported email`. `SourceTime` = the parsed `Date` header; a parse failure leaves it zero. Type `email`. |
| `zip` | Opens the payload as a zip (`invalid zip archive` error otherwise). Every non-directory entry whose lower-cased name ends with one of `exts` (the batch path always passes a non-empty list: the record's `extensions`, else `.txt`, `.md`, `.docx`) is read fully (read errors ignored, partial bytes used) and recursively parsed with format inferred from the entry name — so a nested `.zip`, `.mbox` or `.eml` is parsed when its extension is listed. An entry that cannot be opened is logged and skipped. An error from any entry's parser aborts the whole zip. |

**Email body extraction** (`extractText`): an unparseable or empty `Content-Type` → the body decoded per `Content-Transfer-Encoding`. `multipart/*` without a `boundary` → the raw body undecoded; with one → each part is extracted recursively and the first `text/plain` part with non-empty text is returned, else the first part of any kind with non-empty text (a nested multipart counts through its own result), else `""`. A single `text/*` part → decoded body. Any other single part (an attachment) → `""`. Decoding handles `quoted-printable` and `base64` (standard alphabet); anything else is read raw. Read and decode errors are swallowed and yield whatever bytes were read.

`fragment_limit` stops parsing through a sentinel error (`errBudget`) returned by the sink once the writer is full — checked before each emit, so exactly `limit` fragments are written; that stop is not reported as an error. A cancelled context is likewise not an error (the batch path never cancels its context). Every other parser error is the file's error (§ 3).

## 6. The writer

`newWriter(app, limit, skipDuplicates)`: fails when the `fragment` collection cannot be found. With dedupe on, it preloads the SHA-256 of **every** existing fragment's content (soft-deleted ones included) into memory; a preload failure is logged and dedupe proceeds with an empty set. `limit = 0` means unlimited. `addAt(type, source, content, sourceTime)`: trims content; empty → skipped silently; hash already seen → skipped silently (the hash of a written fragment is added to the set, so repeats within one file are also dropped); otherwise a `fragment` record is saved with `type`, `ingested_via` (the writer's origin), `source`, `content`, and `occurred_at` when `sourceTime` is non-zero (a `ParseDateTime` failure drops it silently). A skipped entry does not count toward the limit and does not change `lastID`. Fragments are saved one at a time, each firing the birth hooks (§ 7); a save error (including record validation — `type` and `ingested_via` are select fields, `content` is required with a 100,000,000-character maximum) is returned to the caller.

## 7. Birth and delete hooks

- `OnRecordCreate("fragment")` (before save, every create path): `occurred_at` defaults to now when zero; `ingested_via` defaults to `"app"` when empty. Validation runs after these defaults.
- `OnRecordAfterCreateSuccess("fragment")` (after the create is durable — for the bookmark and edit paths, after their transaction commits; a rolled-back transaction fires nothing): `colour.Signal()` always — a coalescing wake of the colour worker, which judges the new fragment against every prompt colour past its watermark (`colours.md` § 4). Unless `ingested_via = "import"`: `mapping.SignalAnnotate()` — a coalescing wake of the mapping worker for an annotate-only drain, no map cycle (`map.md` § 2) — and `reconcile.EnqueueWave()` — a debounced request for a speculative wave, a no-op unless `KALAIDO_AUTO_WAVE` is set (`rotation.md` § 3). Imported fragments are left for the completion handoff (§ 3). No thing matching happens at birth; a new fragment joins thing-backed colours only after it is annotated and the map next settles (`colours.md` § 3).
- `OnRecordDeleteRequest("fragment")` — the collection's built-in delete endpoint only. PocketBase checks the collection rule before this hook runs, and the `fragment` delete rule is nil, so a request without superuser auth receives `403` and the hook never runs. For a superuser request: instead of deleting, sets `deleted_at = now` when it is unset and saves (a save error is returned to the request), then returns **204** without calling the next handler — the delete never executes, no `OnRecordDelete` model hook fires, and no cascade runs. A repeat request returns `204` and leaves `deleted_at` unchanged. There is no restore surface and no other soft-delete route. No code path calls `app.Delete` on a fragment. Consequences of a set `deleted_at`: its `colour_fragment` and `fragment_annotation` rows remain; it is excluded by the live filter `deleted_at = ''` from context resolution (`context.md` § 2), the map's pending set and the consolidation date table (`map.md` § 2, § 3 — its annotation row still participates in consolidation, without a date), the colour worker's paging and the colour preview sample (`colours.md` § 4, § 5), the `view_stream` view, the organise fragment count (`organize.md` § 2), and bookmark reuse (a bookmark whose fragment is soft-deleted is re-saved as a new fragment). It is still returned by loads by id (`llmcontext.LoadFragmentsByIDs`: flat hydration of resolved fragment ids, summaries-mode seeding rows, the `read_fragment` tool, colour example blocks) and still seen by the dedupe preload.
